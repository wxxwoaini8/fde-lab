## 五、几条一直在用的规矩

这几条是过程中反复验证有效的，换到新机器上也照此执行：

- **命令要看四件事**：敲哪一行、在哪个终端、看到什么算成功、没看到怎么办。缺任何一件，遇到问题就无从下手。
- **先建环境再装依赖**：一个项目一个虚拟环境，命名统一 `.venv`，不建在项目目录外。
- **提交前先看一眼要提交什么**，再 `add`——这一步挡住过把几百 MB 安装包提交上去的事故。
- **命令优先整段复制，不手打**：中文输入法状态下的引号和空格都不是真的引号和空格，本课程已栽过两次。
- **不写死版本号，写判断规则**：材料里的版本要求都换成了"看第一位是不是偶数即为 LTS"这类可自行判断的规则，避免半年后过期。

## 八、环境变更记录

### 2026-10-16 · Docker 磁盘映像迁到数据盘

为什么做：Docker 的磁盘映像默认落在系统盘，而且只增不减，用久了会把系统盘吃掉。第 6 周和第 11 周还要装数据库镜像，提前挪走更省事。

怎么做的：只能走界面。Settings → Resources → Advanced → Disk image location，把位置改成数据盘（D 盘），再点 Apply & restart。这个版本没有命令行的设置入口。

结果：约 5.6 GB 的映像已迁到数据盘，系统盘可用空间明显增加；随后重启，两个容器（PostgreSQL 与 n8n）都自动恢复运行，数据库连接正常，拉镜像用的加速器配置未受影响。

顺带确认两件事：Docker Desktop 已设为随系统启动——否则重启后容器不会自己回来；两个容器的重启策略都统一成了「自动重启」。

一个别误解的点：C、D、E 三个盘在同一块物理硬盘上，换盘只解决系统盘的空间，不会让 Docker 变快。

### 2026-10-16 · 自检脚本落地，两处环境问题一并修掉

准备周清单里最后一项是「跑一遍环境自检」，但手册里那段示例脚本在本机跑不通：一个工具始终报未安装，另一个报「系统找不到指定的文件」。核查后确认两个工具都装好了，问题在脚本本身——它只会在环境变量 PATH 列出的目录里找命令，而其中一个工具恰好装在一个没被列进去的目录；另一个在 Git Bash 下是没有扩展名的脚本，Python 无法直接把它拉起来。顺手还发现第三条：该工具默认建虚拟环境时不装 pip，导致习惯性地敲 pip 安装会把包装到全局去，项目里反而找不到。

处理方式是把脚本重写成一份能跑的版本，一次验完 20 多项：解释器与虚拟环境、包管理工具、Git 身份、到 GitHub 的 SSH 连接、Node 与 npm、Docker 引擎与两个容器、能否连进数据库、当前目录是否在仓库里、磁盘余量。结论分「通过 / 需注意 / 未通过」三档，未通过项为 0 才算过关；退出码设成 0 或 1，方便以后串进自动化。手册第 2.9 节整节换成了这一版，并配了「现象 → 根因 → 对策」对照表；第五部分的判定标准、失败排查表、真实踩坑清单也同步更新。

环境侧改了两处，改前都做了备份：把那个工具所在的目录加进了用户环境变量（原来不在里面，所以新开终端会提示找不到命令）；给项目虚拟环境补装了 pip。

结果：在工作区根目录跑一次，通过 22 项、需注意 0 项、未通过 0 项。准备周 20 项至此全部具备条件，可以进入第 1 册。

### 2026-10-17 · 换机重建环境

为什么做：换了机器，要按准备周的流程重新把环境立起来。检查时发现旧的全局配置被整份带了过来，里面有三行有问题：一行把 SSH 程序指向一个本机根本不存在的路径；一行把所有 SSH 地址强制改写成 HTTPS（等于把免密彻底废掉）；还有一行关掉了仓库所有权检查。这三行直接沿用，连仓库都连不上。

怎么做的：清掉三行问题配置，补上方案要求的默认分支 main 与行尾符设置，重新生成一把 SSH 密钥。过程中撞到一个跟中文用户名有关的问题——Git 自带的那套 SSH 读不懂中文用户名的家目录，会把它当成一串乱码目录名，于是既找不到密钥、也写不进信任列表，报错看起来像「密钥不存在」。换成系统自带的 SSH 后一次通过。

顺带把用户环境变量里几条损坏条目与死链一并清理并修正（用户名被错误解码成乱码、指向早已卸载的软件），清理前留了备份。

结果：配置核对无误，SSH 密钥已登记到 GitHub，到仓库的连通性验证通过。
