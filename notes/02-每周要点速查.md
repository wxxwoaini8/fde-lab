# 第 1 周 · Python 工程化起步

**一句话目标**：把「我电脑上能跑」变成「别人拿到也能跑、出错能定位」。

**交付物**：一个能给别人用的命令行工具 ＋ 一份清洗日志。

## 一个判据贯穿全周

> 如果一个程序只有你能跑起来，它是脚本；别人拿到也能跑起来，它才是交付物。FDE 卖的是交付物。

## 六个知识点，各自一句话结论

| 知识点 | 核心结论 |
| --- | --- |
| 虚拟环境与依赖 | 一个项目一个 `.venv`；开发用 uv，交付用 `requirements.txt`；每次都要确认 `sys.executable` 落在 `.venv` 里 |
| 项目结构 | 用 `src/` 布局，逼你真安装才导入；`__init__.py` 标记包；`__main__` 守卫防「一导入就执行」 |
| 命令行接口 | 交付物优先 `argparse`（标准库，客户环境一定有）；`type=` 与 `choices=` 把校验前移到入口；退出码 0/1/2 要分开 |
| 日志 | print 没有时间戳、没有级别、不能改去向；四个概念 Logger / Level / Handler / Formatter |
| 异常处理 | 自定义异常层次；消息写给「使用者」——是什么、为什么、怎么办；`raise ... from exc` 保留根因 |
| 配置管理 | 三层覆盖：命令行参数 \> 环境变量 \> 代码默认值；密钥只走环境变量，绝不进代码 |

## 三个必须记住的原理

**1. **`if __name__ == "__main__"`** 防的是什么**

文件被直接运行时 `__name__` 是 `"__main__"`；被 import 时是模块名。所以它是一道开关——只有直接运行才执行主逻辑。去掉它，别人 `import` 你的模块会导致整个脚本被跑一遍。

**2. **`src/`** 那一层为什么不能省**

不加 `src/`，在项目根目录跑 Python 会直接读到源码目录，而不是安装后的包。结果就是「本地能跑、装到客户机器上找不到模块」。加了之后必须真安装，从源头消灭这种差异。

**3. **`raise SystemExit(main())`** 比 **`main()`** 好在哪**

函数返回值会成为进程退出码。0 成功、1 业务错误、2 未预期错误。客户方的定时任务靠退出码判断要不要告警，所以别所有情况都返回 0。

## 命令速查

```bash
# 环境
uv venv --python 3.12 .venv            # 建环境
source .venv/Scripts/activate          # 激活（Windows Git Bash）
python -c "import sys; print(sys.executable)"   # 确认解释器在 .venv 里

# 依赖
uv pip install pandas openpyxl         # 装
uv pip freeze > requirements.txt       # 锁版本
uv pip install -r requirements.txt     # 还原

# 运行
python -m stock_tool.cli -h                          # 看帮助（最便宜的交付文档）
python -m stock_tool.cli -i 文件.xlsx -o 输出目录 -v   # 带参数跑
uv pip install -e .                    # 可编辑安装，之后能直接敲命令名

# Git
git status                             # 先看状态
git add 具体文件名                      # 不用 -A，避免误加无关文件
git commit -m "feat: 库存台账清洗工具可运行版本"
git push
```

## 报错速查

| 报错关键词 | 一句话定位 |
| --- | --- |
| `ModuleNotFoundError` | 解释器不对，或依赖没装 |
| `attempted relative import` | 直接运行了包内文件，改用 `python -m` |
| `KeyError` | 列名 / 键名对不上，先打印实际的名字 |
| `UnicodeDecodeError` | 缺 `encoding=` 参数 |
| `PermissionError` | 文件正被 Excel 打开着 |
| `IndentationError` | 空格与 Tab 混用 |

## 四个高频坑

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| IDE 解释器没选虚拟环境 | import 报找不到模块 | 指到 `.venv/Scripts/python.exe` |
| 全局装包 | 换台机器就崩 | 每次都确认 `sys.executable` 在 `.venv` |
| `.venv` 和 `venv` 混用 | 两个目录两套依赖，彻底混乱 | 一个项目只用一种命名，推荐 `.venv` |
| 依赖没写进文件 | 别人装不起来 | 每加一个依赖就更新 `requirements.txt` |

## 日志的三个细节（容易漏）

- `logger.propagate = False`，否则日志经 root logger 再输出一遍，屏幕出现两份
- `encoding="utf-8"` 必须显式指定，Windows 上 FileHandler 默认 GBK，中文会乱码
- 控制台日志写 `sys.stderr`，这样 `工具 > result.txt` 重定向时日志不会混进结果

## 异常处理的判据

> 只有当你明确知道如何处理这个异常时才捕获；否则让它往上抛，由 CLI 的 main 统一兜住并记录。

明确的反模式：`except: pass`、`except Exception: pass`、循环里捕获后继续、捕获后只 print、用异常做正常流程控制。
