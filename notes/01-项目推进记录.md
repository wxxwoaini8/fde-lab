## 一、时间线

### 2026-09-22 · 起点：先把工具链和节奏定下来

- **决定编辑器只用 CodeBuddy CN，不装 VS Code**。理由：两台机器之间来回切工具的成本最后都算在学习时间上；且 CodeBuddy 是 VS Code 内核，快捷键、命令面板、扩展机制完全一致，教材里的操作步骤照样通用。
- 明确一件事：CodeBuddy 的扩展市场是 **Open VS X**，不是微软市场——所以 Pylance 这类微软专有扩展搜不到（这是授权限制，不是配置错误），Python 类型检查改用 **basedpyright**。
- 规划工作区与磁盘：代码放 E 盘、临时与安装包放 D 盘，避开 C 盘。
- 交付 **分册 00（准备周）**，并顺手修掉一个真实故障：终端里因为中文输入法打出了全角引号，导致报 `0x80070002`。
- 核查 Node/npm 版本：要求写成"第一位数字是偶数即为 LTS"这样的判断规则，而不是写死版本号。

### 2026-09-23 · 教材流水线跑顺，交付分册 01 与 02

### 2026-10-13 · 最密集的一天：从环境到仓库到数据库

**① 全角空格坑（第二次输入法事故）**
`uv venv .venv` 报 `unrecognized subcommand 'venv .venv'`——两个词之间那个"空格"是中文状态下敲的全角空格，终端不认它是分隔符。更麻烦的是**切了英文输入法重敲仍然报错**。最后靠"少敲一半"解决：`uv venv`（不带参数，默认就建 `.venv`）。

**② Git 安装与选项全面核查**
结论：**全部正确**。安装版本的 PATH 选项、身份、默认分支（main）、行尾符（false）、凭据助手都对；系统级配置与全局配置的覆盖关系也正确。

**③ 工作区清理**
首次提交前发现目录里有几百 MB 不该提交的东西：一个编辑器安装包、一份 Python **源码包**（不是能用的解释器）、一个安装包残留，还有一个误建的 `nul` 文件（Windows 保留名，普通方式删不掉，最后用命令行特殊前缀清掉）。清理后建好 `.gitignore`。

**④ 仓库从零到推送成功**
在 GitHub 建空仓库（三个初始化选项一个都不能勾，否则第一次推送会被拒），本地提交、连远端、推送两步都成功；随后补了 README 和前端依赖忽略规则，第二次推送也通过，并且**从远端反向核对过文件清单**。

**⑤ 解释器指向成功**
过程中发现教材里两处不严谨：用 `python -V` 判断"成没成"不可靠（机器上有多套 Python），以及"提示符前会显示 `(.venv)`"只对一种建环境的方式成立。都改掉了，判据换成直接打印"当前这个 python 是谁"。

**⑥ 交付分册 04（前端下·React）**
知识点 11 节 + 一个可运行的看板案例（5 个组件、mock 接口、加载/失败/空三态、导出 CSV）+ 3 练习 + 8 自测。

**⑦ Docker 拉不动镜像，最后配好加速器**
`postgres:16` 拉取报连不上——根因是 `registry-1.docker.io` 被解析到了一个完全无关的 IP 段（DNS 污染），而不是 Docker 装坏了。配了镜像加速器后一次拉通，PostgreSQL 16.15 容器起来、能连进去查询。

**⑧ 按"把今天做过的都补进文档"的要求，教材当天改了三轮**

## 二、踩过的坑（都已写进教材对应章节）

| 坑 | 现象 | 教训 |
| --- | --- | --- |
| 全角引号 | 终端报 `0x80070002`、配置文件静默失效 | 中文输入法会污染引号，也会污染空格 |
| 全角空格 | 命令"看着全对"却报离谱错误 | 命令优先整段复制；报错把"命令＋参数"当成一个词就是全角空格 |
| 提示符显示的不是 `.venv` | 以为解释器没切成功 | 括号里是环境的"提示名"，uv 建的用项目目录名 |
| 新建文件少了扩展名 | 显示为 `README` 而不是 `README.md` | Windows 隐藏已知扩展名，改名要用终端 `mv`，真实名字以 `git status` 为准 |
| 建远端仓库时勾了初始化选项 | `git push` 被拒 | 新建空仓库时三个选项一个都别勾 |
| 项目目录里堆安装包 | 差点提交几百 MB | 提交前先 `status` 看一眼，再看一次 `add --dry-run` 预演 |
| `nul` 保留名文件删不掉 | 普通删除与重命名都被拒绝 | Windows 保留名要用特殊前缀在命令行处理 |
| Docker Hub 拉不动 | 报连不上 registry | 是 DNS 污染，不是 Docker 坏了；配镜像加速器即可 |
| 容器重启后数据库连不上 | 容器没自动起 | 容器默认策略是不会自动重启，要显式设置为自动 |

## 三、过程中立下的规矩

1. **命令类内容四要素齐全**：敲哪一行、在哪个终端、什么算成功、没成功怎么办。
2. **不写死版本号**，写可自行判断的规则 + 指出权威查询位置。
3. **报错要看得出真因**：判据要选"换个机器也一样"的信号，不能选会随工具、目录名变化的输出。
4. **一次只改一个点**（写文档、改配置都是），改完立刻验证。
5. **学的时候自己动手，卡住的时候直接修**：前者给步骤，后者给结果。

### 2026-10-16（续）· Docker 磁盘映像换盘

起因：要求把 Docker 的磁盘映像从系统盘换到数据盘。查下来这个版本没有命令行的设置入口，只能走界面：Settings → Resources → Advanced → Disk image location，改成数据盘后 Apply & restart。顺手把「随系统启动」也打开——否则重启后 n8n 这类容器根本不会自己回来。

结果：映像迁走约 5.6 GB，两个容器（PostgreSQL 与 n8n）在随后的重启里自动恢复，数据库连接正常，镜像加速器配置未受影响。系统盘可用空间从约 36 GB 涨到约 68 GB——映像迁移只占其中一部分，其余是系统在重启前后自己释放的临时文件。

顺手纠正一处旧记录：页面文件大小和系统盘可用空间都是会变的数字，以后要给这类数字，一律在动手前现测，不能拿历史值直接下判断。

### 2026-10-16（续）· 自检脚本修好，准备周收尾

起因：准备周清单最后一项是「跑一遍环境自检」，但手册里那段示例脚本在本机跑不通——一个工具报未安装，另一个报「系统找不到指定的文件」。查下来两个工具其实都装好了，问题出在脚本：一个只会在 PATH 列出的目录里找命令，而该工具装在一个没被列进去的目录；另一个在 Git Bash 下是没有扩展名的脚本，Python 直接拉起必然失败。第三个问题是顺带发现的：该工具默认建虚拟环境时不装 pip。

处理：重写了一份自检脚本，一次验完 20 多项检查（解释器与虚拟环境、包管理、Git 身份、到 GitHub 的 SSH、Node 与 npm、Docker 引擎与两个容器、能否连进数据库、当前目录是否在仓库里、磁盘余量），结论分「通过 / 需注意 / 未通过」三档，判定标准是未通过项为 0；退出码设成 0 或 1，便于串进自动化。三个坑在手册里都写成了对照表，相关的判定标准、失败排查表、踩坑清单同步更新。

环境侧改了两处，改前都留了备份：把该工具所在目录加进用户环境变量（原来不在里面，新开终端会提示找不到命令）；给项目虚拟环境补装了 pip。

结果：工作区根目录跑一次，通过 22 项、需注意 0 项、未通过 0 项。准备周 20 项至此全部具备条件，下一步进入第 1 册。

资料库同步：修订后的分册 00 已更新到「我的文档」（沿用同一个文件与链接，不是新上传一份）；自检脚本也单独放进了「我的文档」，方便在公司电脑上直接取用。

### 2026-10-17 · 换机：Git 环境重建与署名固化

起因：换了机器，要按准备周的流程把环境重新立起来。检查时发现旧的全局配置被整份带了过来，其中三行有问题：一行把 SSH 程序指向一个本机根本不存在的路径；一行把所有 SSH 地址强制改写成 HTTPS（等于把免密彻底废掉）；还有一行关掉了仓库所有权检查，正是 9-24 那次清掉过的那条危险配置。这三行直接沿用，连仓库都连不上。

处理：清掉三行问题配置，补上方案要求的默认分支 main 与行尾符设置（关闭自动转换），重新生成一把 SSH 密钥。

撞到的坑：Git 自带的那套 SSH 处理不了中文用户名的家目录，会把它读成一串乱码目录名，于是既找不到密钥、也写不进信任列表，报错长得像「密钥不存在」。换成系统自带的 SSH 后一次通过，连通验证正常。以后换机若再遇到「密钥明明在、SSH 却说找不到」，先查这条。

另外，旧的用户环境变量里还有几条损坏条目与死链（用户名被错误解码成乱码、指向早已卸载的软件），一并清理并修正，清理前都留了备份。

**署名固化**：为避免凭记忆敲错，把两个值写在这里——**user.name = 王小喵**，**user.email = xuexue\_888@outlook.com**。两处必须一致，邮箱要与 GitHub 账号绑定的一致，否则提交记录挂不到头像下。自查命令：\`git config --global --list\`。

结果：配置核对无误，SSH 密钥已登记到 GitHub，到仓库的连通性验证通过。下一步把仓库克隆到新的练习目录，继续第 1 册。
